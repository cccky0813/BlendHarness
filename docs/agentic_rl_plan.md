# Agentic RL 计划 v2：带关系声明的部件修正（BlendHarness-RL）

> v2（2026-10-25）取代 v1（10/24 的"房间布局"方案）。变更原因见文末"变更记录"。

## 一句话

训练一个小模型：**读入一件物体当前的部件（名字、中心、尺寸）和用自然语言写的设计要求，只改出问题的那几个部件，让所有声明过的关系重新成立。** 奖励来自生成器知道的**形式化关系**，按构造就是准的，不依赖启发式检查，也不依赖裁判模型。

## 为什么是这个任务（证据链）

1. 失败分类：72% 的 Critic 问题是空间问题；接触类修复率 73–85%，**关系类只有 43–45%**（RSI 笔记第 1 站）。
2. 结构审计：真实的悬空、下沉只占约 4%，所以**重点是关系和比例**，不是"连没连上"（第 5 站）。
3. 关系检查器验证：只靠名字和包围盒，**判断不了任意建模的关系**，因为不知道设计意图（第 6 站）→ **奖励必须来自声明过的关系**。
4. 可行性：95% 的建模由多个独立、命名有意义的物体组成，按名字修改部件可行（第 5 站）。
5. 外部：Astra、Kimi K3、Claude + BlenderMCP 的用户反馈里，空间关系和尺度是最常见的投诉。

## 数据模型（v0：轴对齐长方体，绕 z 只转 90° 的倍数）

```
Part      name, center [x, y, z], size [w, d, h]
Relation  （形式化，只给奖励函数用；模型看到的是它的自然语言版本）
  rests_on(A, B)          A 的底面 = B 的顶面，A 的中心落在 B（或一组支撑物合起来）的范围内
  attached(A, B, face)    A 贴在 B 的某个面上，另外两个轴有重叠
  centered(A, B, axis)    A 和 B 在某个轴上中心对齐
  evenly_spaced(G, axis)  一组部件沿某个轴等距，可以带两端的边距
  same_size(G)            一组部件尺寸相同
  mirror(A, B, plane)     A、B 关于某个平面对称
  dim_range(A, d, lo, hi) 某个尺寸落在范围内，例如座高 0.42–0.48 m
  dim_ratio(A, B, d, r)   尺寸比例，例如靠背宽度 = 座面宽度
  grounded(G)             最低点在 z = 0
  no_overlap              除了声明的接触，部件之间不穿插（全局约束）
```

## 题目怎么造

1. **模板**：每类物体是一个参数化生成器，随机采样尺寸，输出**一份合法的装配 + 它满足的全部关系**。按构造就是可解的。
   - 训练模板（7 类）：椅子、桌子、凳子、书架、长椅、梯子 / 双层床、栏杆段；
   - **没见过的模板**（2 类，只用来测泛化）：柜子（带抽屉）、凉亭。
2. **破坏**：按失败分类，选 1–3 种破坏方式施加到部件上，并记录破坏了哪些关系：

   | 破坏方式 | 对应的失败类别 |
   |---|---|
   | 抬起来 | floating |
   | 压下去 | sunk / interpenetration |
   | 平移，打破对齐或贴合 | placement |
   | 某一个轴放大或缩小 | proportion |
   | 组内抖动，打破等距 | placement |
   | 只改镜像对中的一边 | placement / proportion |

3. **模型看到的输入**：物体类别 + 部件清单（名字、中心、尺寸）+ **自然语言的设计要求**（由关系渲染成多种说法）。另外分两个难度档：
   - **带提示**：附上一句类似 Critic 的问题描述，比如"靠背横条挤在一起"，对应方案 C 里 Critic 先发现问题的情况；
   - **不带提示**：模型要自己找出问题。
4. **模型的输出**：只写需要改的部件，例如 `{"edits": [{"name": "Slat_2", "center": [...], "size": [...]}]}`。

**为什么不直接用约束求解器**：如果关系是形式化给出的，求解器确实可以直接解。所以模型看到的是**自然语言**，它的价值在于理解自然语言的要求和问题描述，并把它融进 agent 的循环里。对照组里会放一个"LLM 先解析成形式化关系，再交给求解器"的流水线，用来说明两条路线各自的取舍。

## 奖励

```
format_ok = 0                → reward = 0
r = 0.6 × 满足的声明关系比例
  + 0.3 × [全部关系都满足]
  − 0.1 × 改动惩罚（没被破坏的部件被移动或缩放，按幅度归一化）
```
- 容差：位置 1 cm，或者模型尺寸的 0.5%，取较大者；尺寸差 2%。
- **改动惩罚防钻空子**：没有它，模型可能把所有部件重新摆一遍，满足了关系，但推翻了原本的设计。
- 奖励函数是纯 Python、确定性的，有单元测试；**写好后先用 API 模型的输出人工抽查**，确认分数和人的判断一致，再拿来训练。

## 模型与训练

- Qwen3 0.6B / 1.7B / 4B，用 pass@8 和零样本格式正确率来选。格式正确率低于 90% 时，先用 DeepSeek 生成的正确样本做 SFT 热身。参考论文里全参数微调的格式成功率明显高于 LoRA。
- GRPO：TRL + vLLM，每题 8 个回答（再试 16），每步 32 题，学习率 1e-6（全参数），KL 设为 0 或很小，clip 0.2 / 0.28，按 token 平均 loss，过滤全对或全错的组。
- 训练时盯：奖励的均值和方差、全对或全错组的比例、回答长度、熵、改动惩罚，每 N 步人工看几条样本。

## 评测

| 测试集 | 内容 |
|---|---|
| 同分布 | 训练模板，新的随机种子，200 题 |
| **没见过的模板** | 柜子、凉亭，100 题 |
| 按破坏类型 | 每种破坏方式分别统计 |
| **真实失败**（之后补） | 新基线里 Coder 声明过关系、但关系不成立的建模 |

- 指标：全部关系都满足的比例、关系满足率、改动惩罚、格式正确率；带提示和不带提示分开报告。
- 对照组：什么都不改（下界）、DeepSeek、Sonnet、Astra / K3（只跑一小部分）、"LLM 解析 + 求解器"、训练前和训练后的 Qwen。
- 统计：95% 置信区间，同题配对比较。

## 接回 BlendHarness（之后）

- **Coder 先声明意图**：建模时输出一份部件和关系的计划（结构化 JSON）。这样 harness 就能用同一个奖励函数**验证 Coder 的结果**，第 6 站说的"没有意图就没法验证"的问题也一起解决了。
- 验证不通过，或者 Critic 提出空间类问题时，交给修正模型修改，再追加一段固定格式的修正脚本。
- A/B：用 `fork_from` 从同一个 round0 分叉，比较"修正模型修"和"Coder 自己修"，指标是声明关系的满足率和最终通过率。
- 修复 bug 之后系统变了，所有基线都要**在 commit 固定后重新跑**。

## 代码组织

新的顶层包 `spatialrl/`，不依赖 `blendharness`，训练机上只需要装这一个包：
```
spatialrl/
  geometry.py     长方体、间隙、重叠
  relations.py    形式化关系和检查（奖励的核心）
  templates/      每类物体一个生成器
  corrupt.py      破坏方式
  render_text.py  关系 → 多种自然语言说法；破坏 → 问题描述
  reward.py       解析输出 + 计算奖励
  dataset.py      生成 train / dev / test / unseen 的 jsonl
tests/spatialrl/  每个模块都有单元测试；另加一个"关系 → 构造合法装配 → 全部满足"的性质测试
```
